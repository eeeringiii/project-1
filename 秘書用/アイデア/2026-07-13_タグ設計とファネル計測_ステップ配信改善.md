# タグ設計・ファネル計測・ステップ配信改善（退職給付金の窓口）

- 作成日：2026-07-13
- 対象：LINE公式アカウント「退職給付金の窓口」（エルメ運用）
- 目的：①友だち追加→成約までのファネルをタグで計測 ②離脱ポイントを可視化 ③ステップ配信を改善して予約率・面談実施率・成約率を上げる
- 商材前提：初回面談は無料・LINE音声通話。退職・退職給付金の相談

---

## 1. 設計方針

タグを**4種類の役割**に分けて管理する。混ぜると計測が崩れるので、役割ごとにプレフィックスを付けて整理する。

| 役割 | プレフィックス | 個数ルール | 用途 |
| --- | --- | --- | --- |
| A. ファネル段階（ステータス） | `F` + 番号 | **1人1つ**（進むたび付け替え） | ファネル計測の主軸 |
| B. 流入経路 | `経路_` | 複数可・不変 | どこから来たかを分析 |
| C. 属性 | `属性_` | 複数可 | セグメント配信・分析 |
| D. 制御 | `制御_` | 複数可 | 配信の分岐・除外 |

ポイント：**Aだけは「今どの段階か」を1つに保つ**。段階が進んだら前の段階タグを外し、新しい段階タグを付ける（エルメのアクションで「タグを付ける／外す」を同時設定）。これで各段階の人数＝そのままファネルになる。

---

## 2. タグ一覧（この名前でエルメに作成）

### A. ファネル段階タグ（1人1つ・排他）
| タグ名 | 意味 | 付与タイミング |
| --- | --- | --- |
| `F1_友だち追加` | 登録直後 | 友だち追加時（あいさつメッセージのアクション） |
| `F2_予約ページ閲覧` | 予約URLをタップ | 予約URLのクリック計測で付与 |
| `F3_予約完了` | 面談を予約した | カレンダー予約の完了アクション |
| `F4_面談実施` | 面談を受けた | 面談後（手動 or 面談後アクション） |
| `F5_手続き中` | 給付金手続き等に進行 | 手動 |
| `F6_成約` | 成約・サポート契約 | 手動 |
| `F9_離脱_無反応` | フォロー後も無反応 | ステップ配信終了時に自動付与 |
| `F9_キャンセル` | 予約後にキャンセル | 手動 or キャンセル時 |
| `F9_無断欠席` | 予約したが未出席（No-show） | 面談当日後に手動 |
| `F9_対象外` | 対象外・配信停止 | 手動 |

> `F9_`系は「そこで止まった／離脱した」人。次の再アプローチ設計に使う。

### B. 流入経路タグ（複数可・不変）
- `経路_Google広告`
- `経路_LINE広告`
- `経路_X`
- `経路_Instagram`
- `経路_TikTok`
- `経路_紹介`
- `経路_検索その他`

> 付与方法：**パラメータ付き友だち追加URL**（媒体ごとにURLを分け、追加時にタグ付与）／エルメの流入経路分析機能。広告ごとの費用対効果（予約率・成約率）が出せる。

### C. 属性タグ（複数可）
- `属性_在職中` / `属性_退職予定あり` / `属性_退職済`
- `属性_20代` / `属性_30代` / `属性_40代` / `属性_50代以上`
- （任意）`属性_自己都合` / `属性_会社都合`

> 面談前アンケート（フォーム作成）や1:1チャットで取得。給付金は離職理由・年代で条件が変わるため、後の個別最適配信に効く。

### D. 制御タグ（配信の分岐・除外）
- `制御_予約済`：**未予約ナーチャリングの除外キー**（F3付与と同時に付ける）
- `制御_面談後フォロー対象`：面談後ナーチャリング配信の対象
- `制御_再面談希望`：再アプローチ配信の対象
- `制御_配信停止希望`：全一斉配信から除外（最優先で尊重）

## 3. タグ付与フロー（どこで自動的に切り替わるか）

```
友だち追加
  └─ [F1_友だち追加] 付与 ＋ 経路タグ付与
        │
        ▼ 予約URLをタップ（クリック計測）
  └─ [F2_予約ページ閲覧] 付与 ／ F1 を外す
        │
        ▼ カレンダー予約 完了
  └─ [F3_予約完了] 付与 ／ F2 を外す ＋ [制御_予約済] 付与
        │        （＝この瞬間、未予約ナーチャリングから自動離脱）
        ▼ 面談実施
  └─ [F4_面談実施] 付与 ／ F3 を外す ＋ [制御_面談後フォロー対象] 付与
        │
        ▼ 手続き → 成約
  └─ [F5_手続き中] → [F6_成約]
```

離脱系（自動/手動）：
- 未予約フォロー終了後も無反応 → `F9_離脱_無反応`
- 予約後キャンセル → `F9_キャンセル` ＋ `制御_再面談希望`
- No-show → `F9_無断欠席` ＋ `制御_再面談希望`

## 4. ファネルKPI（タグ別友だち数で毎週見る）

| 指標 | 計算 | 目安の見方 |
| --- | --- | --- |
| 予約ページ到達率 | F2 ÷ F1 | あいさつ文・導線の魅力 |
| **予約率** | F3 ÷ F1 | 最重要。全体の入口効率 |
| 面談実施率 | F4 ÷ F3 | リマインド・No-show対策の効き |
| 成約率 | F6 ÷ F4 | 面談品質・クロージング |
| 離脱率 | F9系合計 ÷ F1 | どこで失っているか |

見方のコツ：
- **F1→F2で大きく落ちる**＝あいさつメッセージ／予約導線の問題 → 文言・ボタン位置を改善
- **F2→F3で落ちる**＝予約ページの入力ハードル → 項目を減らす・日程の空きを増やす
- **F3→F4で落ちる**＝No-show → リマインド強化（前日・直前）＋前入金/前準備の演出
- 経路タグ×F3/F6 で、**媒体ごとの予約率・成約率**を比較し予算配分を最適化

> エルメの「データ分析」やタグ別友だち数を、毎週同じ曜日にスプレッドシートへ転記すると推移が見える。まずは手動記録でOK。

## 5. ステップ配信の改善案

### 現状
未予約者フォロー（友だち追加起点）A:翌日／B:3日後／C:7日後 の3通のみ。

### 改善①：除外と計測を全通に仕込む
- 全通の配信条件に **`制御_予約済`を除外**（予約したら自動で止まる）
- 各配信の予約URLに**クリック計測**を設定。タップした人に `F2_予約ページ閲覧` を付与
- C（7日後）まで無反応なら **`F9_離脱_無反応`** を付与してステップ終了 → 以降は月1回の一斉配信へ

### 改善②：無反応者と反応者で出し分け
- A・Bを**開封/クリックで分岐**：クリックした人＝関心高 → 早めに個別1:1チャットへ誘導する短い追撃を1通追加
- 無反応が続く人には、Cで「無理に決めなくて大丈夫」トーンを強める（現行踏襲）

### 改善③：新シナリオを2つ追加

**(a) No-show／キャンセル 再アプローチ**（`制御_再面談希望` 起点）
- 当日〜翌日：「またいつでも」再予約リンク。責めない
- 3日後：日程が合わなかった前提で候補提示

**(b) 面談後ナーチャリング**（`制御_面談後フォロー対象` 起点）
- 面談当日：お礼＋次アクション（既存④）
- 3日後：不安解消・よくある質問（既存⑤）
- 7日後：手続きの流れを1枚で説明＋背中を押す（新規1通）
- ※ `F6_成約` が付いたら除外

### 改善④：一斉配信（緩いナーチャリング）
- 未成約の全員へ**月1回**、給付金・退職の役立ち情報を配信し、想起を維持
- `制御_配信停止希望` は必ず除外

## 6. 導入の順番（おすすめ）
1. **A（ファネル段階）＋ `制御_予約済` を先に作る** … これだけで計測と除外が回り始める
2. 予約完了アクションに `F3_予約完了` ＋ `制御_予約済` を設定（F2を外す）
3. 予約URLのクリック計測 → `F2_予約ページ閲覧`
4. 未予約フォローに除外・計測・`F9_離脱_無反応`終了を追加（改善①）
5. 経路タグ（媒体別URL）→ 費用対効果の比較
6. 新シナリオ (a)(b) を追加

> まず1〜2だけでも「予約率」が測れるようになります。全部を一度に作らず、上から順に。
