# マニュアル：HP更新（NEWS更新・サイト改修・月次解析）

## 目的
「生きているサイト」を維持する（HPリニューアル計画の勝ち筋③更新の鮮度）。
更新は秘書がすべて実務を担い、えりんぎさんは指示と承認のみ。

## 対象
- リポジトリ：この作業リポジトリ（`taisei-site/`、Next.js 16 + Tailwind CSS 4）
- 公開先：Vercel（main ブランチ更新で自動デプロイ）
  - 仮公開URL：https://project-1-zeta-sooty.vercel.app （独自ドメイン接続後はここを書き換える）

## 頻度・トリガー
- **NEWS更新**：情報確定の都度（原則、依頼当日に反映）
- **サイト改修**：えりんぎさんの指示ベース
- **アクセス解析レポート**：月次（解析導入後に開始）

## 手順

### 1. NEWS更新（即日反映フロー）
1. えりんぎさんが秘書に情報を投げる（形式自由。日付・タイトル・本文・リンクがあれば十分）
2. 秘書がNEWS記事としてコードに反映 → ビルド確認 → main へ反映 → 自動デプロイ
3. デプロイ後、秘書が実ページを確認して完了報告（URL付き）
4. 対応する SNS 告知が必要か判断し、必要なら `SNS運用.md` のフローを同時に起動
- ※microCMS 接続後（HP計画 Phase 2 の残タスク）は、スタッフ入稿も可能になる。導入したらこの手順を書き換える

### 2. サイト改修
1. 指示内容を確認し、影響範囲を秘書が説明してから着手
2. 実装 → スクリーンショット等での見た目確認 → えりんぎさん承認 → 公開
3. **公開前チェック（毎回・恒久原則）**：
   - 誰のサイトか最初の画面で分かるか
   - 文字コントラスト WCAG AA（4.5:1）維持
   - タップ目標 約44px 確保
   - 英語ラベルに必要な日本語併記
   - ページ最下部にも次の行き先があるか
   - スマホ表示を最優先で確認

### 3. 月次アクセス解析（解析導入後）
- 見る指標：訪問数／流入元（SNS別）／よく見られたページ／BUSINESSフォーム到達数
- 月初に前月分レポートを `秘書用/日報/` へ保存し、改善案を1つ以上添える

## 自動化メモ（Phase 4）
- アクセス解析の自動集計 → 月次レポート自動生成
- NEWS更新とSNS告知下書きの同時生成（1指示で両方）
